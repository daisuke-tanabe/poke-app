# ディレクトリルール

## 概要

`src/` ディレクトリにおけるルール。

## components

`src/components/` ディレクトリは、単一責任の基本要素を格納する。

### 特徴

- 単一のHTML要素をラップ・拡張したシンプルなコンポーネント
- UI要素の基本的な見た目と振る舞いを定義
- 再利用可能で汎用的な設計
- ビジネスロジックを持たない

**例：**
- `Button` - ボタン要素のスタイリングと基本的な振る舞い
- `Input` - 入力フィールドのスタイリングと基本的なバリデーション
- `Card` - カードレイアウトのスタイリング
- `Badge` - バッジ表示のスタイリング

## feature

`src/feature/` ディレクトリは、機能コンポーネントを格納する。

### 特徴

- 独立したビジネスロジックを持つ機能単位のコンポーネント
- 複数のページや他の機能から使用される
- 特定のドメインやユースケースに特化した機能
- データの取得・更新・状態管理を含む

**例：**
- ポケモン検索機能
- ユーザー認証機能
- ファイルアップロード機能

## shared

`src/shared/` ディレクトリは、アプリケーション全体で共有される汎用的なユーティリティ、ライブラリ、型定義を格納する。

## ディレクトリ構造

```
src/shared/
├── constants/      # 定数定義
├── lib/            # 複雑なロジック・設定
├── utils/          # 純粋関数・ユーティリティ
└── types/          # 共通型定義
```

## utils vs lib の分類基準

### `src/shared/utils/`

純粋な関数・ユーティリティを配置する：

- 引数を受け取って値を返すだけの関数
- 外部の状態に依存しない関数
- どこでも再利用できる関数  
- テストが簡単な関数
- `index.ts` のバレルファイルからexport

**例：**
- CSS クラス結合関数（`cn`）
- 配列検索ヘルパー（`findOrThrow`）  
- アサーション関数（`assertFound`）
- 数値変換・バリデーション関数

### `src/shared/lib/`

設定やコンテキストが必要な機能を配置する：

- 設定やコンテキストが必要な機能
- 内部状態を持つ機能
- アプリケーション固有のロジック
- 複数の機能を統合したもの

**例：**
- データベース接続設定（`prisma.ts`）
- バリデーションスキーマ（`searchParamsSchema.ts`）
- 設定オブジェクト・シングルトンインスタンス
- HTTP通信関連の設定
- エラーハンドリング機能
- 状態管理関連

## 判定チェックリスト

### utils に配置する場合（すべて Yes であること）

- ✅ 引数を受け取って値を返すだけか？
- ✅ 外部の状態（グローバル変数、API等）に依存しないか？
- ✅ 副作用を持たないか？
- ✅ 同じ引数では常に同じ結果を返すか？（純粋関数）
- ✅ どんなコンポーネントからでも使えるか？
- ✅ テストで引数と戻り値のペアだけを検証すれば十分か？

### lib に配置する場合（いずれか一つでも Yes）

- ❓ 設定やコンテキストに依存するか？
- ❓ 内部状態を持つか？
- ❓ 副作用（API通信、localStorage等）があるか？
- ❓ アプリケーション固有のビジネスロジックか？
- ❓ 複数の機能や依存関係を組み合わせているか？
- ❓ クラス定義やシングルトンオブジェクトか？

## 依存関係ルール

utils と lib 間の依存方向は以下の通りに制限される：

```
utils → lib （許可）
lib → utils （禁止）
```

**理由：**
- `utils` は純粋関数で外部依存を持たない
- `lib` はより複雑で状態や設定に依存する機能
- 純粋関数（utils）から複雑な機能（lib）への依存は自然
- 複雑な機能（lib）が純粋関数（utils）に依存すると循環依存の原因となる

## インポート規則

### utils のインポート
```typescript
// バレルファイルから一括インポート（推奨）
import { cn, findOrThrow, assertFound } from '@/shared/utils';

// 個別インポート（必要に応じて）
import { cn } from '@/shared/utils/cn';
import { findOrThrow } from '@/shared/utils/findOrThrow';
```

### lib のインポート
```typescript
// バレルファイルから一括インポート（推奨）
import { prisma, searchParamsSchema } from '@/shared/lib';
```

## 注意事項

1. **純粋関数の保持**: utilsに配置する関数は副作用を持たないよう注意する
2. **バレルファイルの活用**: utilsは`index.ts`経由でのインポートを推奨
3. **依存関係の監視**: lib → utils の逆依存が発生しないよう注意する
4. **テスタビリティ**: utilsの関数は単体テストが容易になるよう設計する
5. **再利用性**: どの機能からでも安全にインポートできることを確認する
